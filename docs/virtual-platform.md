# Virtual platform: I/O, input, audio, save and lifecycle

**Status:** proposed abstractions. This is a host architecture, not a published emulation of proprietary Xbox services.

## 1. Virtual filesystem (VFS)

Mounts for self-authored test applications:

| Guest-neutral mount | Host backing | Access |
| --- | --- | --- |
| `game:/` | Explicit user-selected fixture directory | Read-only |
| `cache:/` | Project application-data cache | Read/write |
| `save:/` | Separate sandbox test profile | Transactional |

`game:/` is a **Directbox test label**, not a claim about Xbox path names. Canonicalize every path, reject traversal outside the selected root, reject ambiguous symlinks unless policy permits them, and preserve host error details.

Async reads expose a token, cancel handle and completion event. Future streaming research should measure bandwidth, queue depth, latency and cache hit rate with freely redistributable data. Do not assume DirectStorage on PC duplicates console I/O behavior automatically.

## 2. Input

Normalize host GameInput/XInput (where available) into:
`InputEvent { device_id, timestamp_ns, kind, code, value }`.

Requirements:
- deadzone curves defined explicitly;
- controller hotplug events;
- vibration as an optional host adapter;
- keyboard mapping only in test profiles;
- deterministic replay of captured *project-owned* input.

## 3. Audio

Build a neutral graph:
`AudioDevice -> Voice -> BufferQueue -> Mix -> WASAPI/XAudio2`.

Start with PCM test tones generated by code. Resampling, channel layout, looping, clock alignment and device loss each need independent tests. Console-specific compressed codecs or DSP behavior are separate research problems.

## 4. Saves

Use a transactional test-store with an atomic temporary-file + rename strategy where supported, checksums, rollback, and per-test sandbox directories. Cloud saves and account identity cannot be claimed by this local service.

## 5. Lifecycle

A synthetic application lifecycle state machine:

```text
Created -> Initializing -> Active -> Suspending -> Suspended
                               ^                 |
                               +----- Resuming <-+
Active -> Closing -> Closed
```

All transitions must cancel or drain outstanding work predictably. Invalid transitions return typed errors and do not corrupt resource state.

## 6. Security boundary

Never auto-run downloaded packages. No console keys, firmware, proprietary game data, or authentication tokens belong in the repository. The initial code path is non-executing inspection, and experimental execution should use self-authored fixtures with explicit opt-in.
